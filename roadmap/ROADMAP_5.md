## 0. 이 로드맵의 전제

로드맵 4의 결론 일부와 어긋나는 부분이 있습니다. 그대로 갑니다. 과거 로드맵은 소급 수정하지 않고, 새 로드맵이 앞선 결정을 덮어쓰는 방식으로 진행합니다.

구체적으로 달라지는 것은 두 가지입니다.

**맵1은 별내림 천문대 하나입니다.** 로드맵 4 작업 D는 1구역 안을 방위로 8등분해 각 구간에 원작 지역명을 붙였지만, 그 8개 이름은 각각 나중에 만들 별도 맵(맵2~맵8)의 이름입니다. 방위별로 지면 톤과 밀도가 달라지는 연출(`areaAt`)은 그대로 두되, 이번 로드맵에서는 그것을 "지역"이 아니라 **한 맵 안의 지형 성격 차이**로 다룹니다.

**지면이 평평하다는 전제가 깨집니다.** 지금까지 모든 오브젝트는 높이 0의 구면 위에 있었습니다. 이제 지면에 높이가 생깁니다. 다만 아래 10장에 적은 대로, 이 높이는 **구체 투영 수식에 손대지 않는 방식**으로만 들어갑니다.

| 1:32 | 비행정이 하강. 아래로 **잔디 고원과 깎아지른 황토색 절벽**, 그 사이 골짜기가 보임 |
| 1:40 | 착륙. **나무 데크**, 녹색 잎 깃발, 왼편에 **폭포와 못**, 울타리가 양쪽에 박힌 **흙길**, 바닥에 **청록색으로 빛나는 별**, 능선에 **선돌 몇 개** |
| 1:55 | 화면 중앙에 **"에버그린 / 별내림 천문대"** 대형 타이틀. 비행정, 등불, 돌계단 |
| 2:13 | NPC 그레이스와 대화. 배경에 **넓은 돌계단**이 언덕으로 올라감. 등불, 나무통, 부서진 석재 |
| 2:37 | NPC 은비와 대화. **광장이 물로 삼면이 둘러싸인 반도**이고, 뒤쪽 **나무다리** 하나가 건너편 단구로 이어짐 |
| 2:50 | 광장 전경. 폭포, 단차진 고원, 나무 상자와 가마솥 |
| 3:16 | 다리를 건넌 뒤 **파란 슬라임 사냥터**. 완만한 풀 비탈, 붉은 버섯, 작은 못, 오른쪽으로 빠지는 흙길 |

여기서 읽히는 구조가 이번 맵 재구성의 뼈대입니다.

> **착륙 데크 → 물로 둘러싸인 광장(NPC) → 다리 하나 → 비탈 사냥터 → 길을 따라 바깥으로**

광장은 사방이 트인 들판이 아니라 **나가는 곳이 정해진 방**입니다. 그래서 첫 화면이 어수선하지 않고, 어디로 가야 할지 고민할 필요가 없습니다. 지금 우리 맵이 스폰 직후 막막한 이유가 정확히 이것의 반대이기 때문입니다.

## 2. 작업 A — 높이와 점프 (Space)

### 2-1. 원칙 — 높이는 화면에만 있고, 시야에는 없다

구체 투영에서 높은 곳에 올라가면 지평선이 멀어져야 맞습니다. 하지만 `project()`는 거리 하나로 화면 좌표와 축소율을 동시에 내는 구조라, 여기에 높이를 물리면 수식 전체를 다시 짜야 합니다. 그 수식은 원작 영상을 분석해서 얻은 이 프로젝트의 핵심 자산이라 건드리지 않습니다.

그래서 이번 높이는 **순수한 화면 세로 오프셋**입니다. 단 위에 올라가도 더 멀리 보이지는 않습니다. 이것은 버그가 아니라 의도된 단순화이고, 실제로 플레이해보면 단차가 20~70 수준이라 지평선 변화가 있어야 할 만큼 높지도 않습니다.

### 2-2. 플레이어 점프

플레이어는 항상 투영의 극점, 즉 화면 정중앙에 그려집니다. 그래서 점프는 **플레이어 스프라이트를 `z`만큼 위로 올려 그리는 것**이 전부입니다. 그림자는 지면에 그대로 남겨서 높이감을 만듭니다.

```js
const JUMP_V = 260;      // 초기 속도
const GRAVITY = 900;     // 중력
const STEP_UP = 14;      // 이 이하 단차는 그냥 걸어 올라감
const JUMP_CLEAR = 34;   // 점프로 오를 수 있는 최대 단차
```

`JUMP_V = 260`, `GRAVITY = 900`이면 최고 높이 약 37, 체공 약 0.58초입니다. 캐릭터 반지름이 15이니 자기 키의 두 배를 조금 넘게 뜁니다.

조작은 `Space`입니다. 지도가 열려 있을 때(`mapView > 0`)와 구역 전환 중(`transition`)에는 무시합니다. 모바일은 조이스틱 반대편에 점프 버튼을 하나 놓습니다.

### 2-3. 지형 높이

지면 높이는 **단(plateau)의 목록**으로 표현합니다. 원과 사각형 두 가지면 충분합니다.

```js
// 단 하나: 발자국 도형 + 윗면 높이
{ shape: 'circle', x, y, r, top }
{ shape: 'rect',   x, y, w, h, angle, top }

function groundHeightAt(x, y) {
  let top = 0;
  for (const p of currentZone.plateaus) if (contains(p, x, y)) top = Math.max(top, p.top);
  return top;
}
```

높이는 네 단계로 규격화합니다. 규격을 정해두지 않으면 "걸어 올라가지는 높이"와 "점프해야 하는 높이"가 뒤섞여서 플레이어가 규칙을 못 배웁니다.

| 이름 | 높이 | 오르는 법 |
| --- | --- | --- |
| 계단 한 칸 | 12 | 그냥 걸어서 (STEP_UP 14 이하) |
| 낮은 턱 | 20 | 점프 |
| 단구 | 40 | 못 오름 — 계단이나 경사로로 돌아가야 함 |
| 절벽 | 70 | 못 오름 — 맵의 벽 |

돌계단은 높이 12짜리 단을 네 칸 쌓아 만듭니다. 그러면 별도 처리 없이 걸어서 올라가집니다.

### 2-4. 이동 판정

`player.z`는 **지면 기준 절대 높이**로 둡니다. 높이 40짜리 단 위에 서 있으면 `z = 40`이고, 거기서 점프하면 77까지 올라갑니다. 그러면 기존 `collides(x, y)`에 한 줄만 붙이면 끝입니다.

```js
function collides(x, y, z) {
  // ... 기존 장애물 · 랜드마크 · 월드 경계 판정 그대로 ...
  const top = groundHeightAt(x, y);
  if (top - z > STEP_UP) return true;   // 오르기엔 너무 높은 벽
  return false;
}
```

즉 **올라서려는 단의 윗면이 지금 내 발 높이보다 STEP_UP 넘게 높으면 벽**입니다. 서 있을 때는 `z`가 곧 발밑 지면 높이라 자동으로 맞고, 점프 중이면 `z`가 올라가 있으니 낮은 턱은 그냥 넘어갑니다. 판정식이 하나라서 걷기와 점프를 따로 처리할 필요가 없습니다.

내려오는 것은 막지 않습니다. 단 밖으로 걸어 나가면 `z`가 현재 지면 높이보다 높아지므로 자동으로 낙하 상태가 되고, 중력으로 떨어집니다. 낙하 피해는 없습니다(전투가 없으므로).

`tryMove()`의 미끄러짐 처리는 그대로 씁니다. 벽에 비스듬히 부딪히면 벽을 따라 미끄러지는 기존 동작이 단차에도 그대로 적용됩니다.

### 2-5. 그리기

단 자체와 단 위의 오브젝트는 **이미 있는 `projectTall(x, y, height)`을 그대로** 씁니다. 새 투영 함수를 만들지 않습니다. 단의 윗면은 잔디, 옆면은 황토색 절벽면(가로 줄무늬 층)으로 그려 원작의 단면 느낌을 냅니다.

정렬(`solids` 배열의 painter's algorithm)은 기존 그대로 화면 Y 기준입니다. 단은 `layer 0`과 오브젝트 사이에 새 레이어로 들어갑니다.

플레이어가 점프 중일 때는 가림 판정(`objectReach` / `drawPlayerOutline`)에 플레이어의 화면 Y 오프셋 `-z`를 함께 넘겨서, 뛰어올라 나무 위로 머리가 나오면 점선 테두리가 풀리게 합니다.

## 3. 작업 B — 물

물은 두 종류만 둡니다. 종류가 늘면 플레이어가 어디를 건널 수 있는지 매번 시험해봐야 합니다.

| 종류 | 깊이 | 동작 | 생김새 |
| --- | --- | --- | --- |
| 여울 | -6 | **지나갈 수 있음.** 이동 속도 0.55배, 발밑에 물보라 | 바닥 자갈이 비치는 옅은 하늘색 |
| 깊은 물 | -30 | **막힘.** 다리로만 건넘 | 짙은 파랑, 물결 무늬, 가장자리에 흰 포말 |

물은 `plateaus`와 같은 도형 목록으로 두되 `top`이 음수인 것으로 구분합니다. 따라서 `groundHeightAt()` 하나로 땅과 물을 같이 다룹니다. 깊은 물은 단순히 "들어가면 막히는 영역"으로 처리합니다.

폭포는 절벽면에 붙는 장식입니다. 절벽 높이만큼 흰 세로 띠를 그리고 아래쪽 못에 포말 원을 겹칩니다. 물리적 판정은 없습니다.

미니맵과 구역 지도에도 물과 단구를 그립니다. 지금은 탐험한 영역이 초록 한 색으로만 칠해지는데, 그 아래에 물(파랑)과 단구(황토) 실루엣을 미리 깔아두고 그 위에 기존 fog를 덮으면, **걸어서 드러난 만큼만 지형이 보이는** 구조가 유지되면서도 지도가 훨씬 읽을 만해집니다.

## 4. 작업 C — 맵 재구성

### 4-1. 광장 — 물로 둘러싸인 반도

스폰 지점을 원작처럼 **나가는 곳이 두 군데뿐인 광장**으로 만듭니다.

| 요소 | 좌표 / 범위 | 값 |
| --- | --- | --- |
| 광장 바닥 | 중심 (0,0), 반경 170 | 높이 0, 흙바닥 |
| 물 반달 | 방위 75°~300°, 반경 185~340 | 깊은 물 |
| 개울(여울) | 방위 55°~75°, 반경 185~340 | 여울 — 샘물 지대에서 흘러나오는 물줄기 |
| 절벽 | 방위 300°~10°, 30°~55° | 높이 70 |
| 폭포 | 방위 330° 절벽면 | 장식, 아래 못으로 떨어짐 |
| **나무다리** | 방위 145°~155°, 반경 180~350 | 높이 10, 폭 40 — **통로 1** |
| **돌계단** | 방위 10°~30°, 반경 170~240 | 12씩 4칸 → 높이 48 단구 — **통로 2** |

기존 랜드마크 **샘물 지대(230,-110)** 는 방위 64.4°, 거리 255라 마침 개울 구간 한가운데에 놓입니다. 좌표를 옮기지 않고도 "샘물에서 흘러나온 물이 광장을 감싸고 돈다"는 설명이 그대로 성립합니다.

### 4-2. 광장 안의 것들

원작 1:40~2:50에 나오는 것을 그대로 옮깁니다.

- **착륙 데크** — 광장 북서쪽 (-90,-90) 부근, 나무 바닥 높이 8, 난간 포함
- **비행정** — 데크 위. 우리는 아직 탈것이 없으므로 **움직이지 않는 배경 오브젝트**입니다. 나중에 맵 간 이동을 만들 때 이 자리가 그대로 출발점이 됩니다
- **잎 깃발** — 데크 옆, 청록색 삼각 깃발에 잎 문양
- **등불 기둥 2개** — 데크 입구와 다리 어귀
- **나무 상자·통 무더기** — 3~4곳
- **가마솥** — 광장 중앙 부근
- **부서진 석재** — 계단 아래에 흩어진 조각들
- **선돌 3개** — 계단 위 단구 가장자리. 원작 뮤렌 습지대 퀘스트에 "천문대의 거석 세 개를 통과하는 태양빛으로 정확한 시간을 잰다"는 대목이 있어, 천문대다운 물건으로 이것을 씁니다

### 4-3. 광장 바깥 — 비탈과 공터

다리를 건너면 원작 3:16처럼 **완만한 풀 비탈**이 나옵니다. 높이 0에서 20까지 서서히 올라가는 넓은 경사지이고, 여기가 첫 사냥터 자리입니다(9장).

계단을 올라가면 높이 48의 **단구 고원**입니다. 여기서부터 기존 랜드마크들이 있는 바깥 들판으로 이어집니다.

### 4-4. 스케일 점검

월드 반경은 1500 그대로 둡니다. 플레이어 속도 200이므로 광장(반경 170)을 가로지르는 데 1.7초, 다리를 건너 사냥터까지 약 3초, 월드 끝까지 약 7.5초입니다. 광장이 전체의 11%를 차지하는 셈이라 "도입부"로 적당합니다.

## 5. 작업 D — 길이 길 노릇을 하게

지금 `pathTiles`와 `pathFences`는 순전히 장식입니다. 길 위를 걷든 옆 풀밭을 가로지르든 아무 차이가 없습니다.

길을 **간선 2개 + 지선 3개**로 다시 깝니다.

| | 경로 | 잇는 곳 |
| --- | --- | --- |
| 간선 1 | 광장 → 나무다리 → 비탈 사냥터 → 남동쪽 바깥 | 포탈 방향 |
| 간선 2 | 광장 → 돌계단 → 단구 고원 → 북동쪽 바깥 | 바위산·샘물 방향 |
| 지선 | 간선에서 갈라져 랜드마크로 | 거대 고목 / 석조 유적 / 빛나는 결정 |

중요한 것은 **길 밖을 막지 않는다**는 점입니다. 완전히 막으면 오픈월드가 복도가 되고, 로드맵 1부터 지켜온 "걸을수록 지평선 너머가 드러난다"는 감각이 죽습니다. 대신 이렇게 합니다.

- 길 위는 장애물이 없고 평평합니다
- 길 옆은 덤불과 나무 밀도를 **1.6배**로 올려서 지나갈 수는 있지만 성가시게 합니다
- 물과 단구는 실제로 막습니다 — 우회하려면 한참 돌아가야 합니다
- 길 양쪽에 원작처럼 **말뚝 울타리**를 박아 시각적으로도 길이 읽히게 합니다

결과적으로 "길을 따라가는 게 빠르지만, 굳이 벗어나고 싶으면 벗어날 수 있는" 상태가 됩니다. 이게 원작 영상에서 실제로 느껴지는 감각입니다.

## 6. 작업 E — 떨어진 별

지명의 근거인데 지금 맵에 없습니다. 로드맵 4에서 "기존 `spores`를 재활용해 중심부 밀도를 올리자"고 적었지만 실제로는 들어가지 않았습니다.

원작에서는 **바닥에 박혀 청록색으로 빛나는 원반**입니다. 가까이 가면 위로 옅은 빛기둥이 솟고, 주변에 반짝임이 떠다닙니다.

```js
// 별 하나
{ x, y, r: 18 + rand()*10, phase: rand()*Math.PI*2 }
```

- 개수 14개, 중심 반경 700 안에 우선 배치 (천문대 일대가 가장 조밀)
- 길가와 공터를 우선하고, 나무·바위와 겹치지 않게 스캐터에서 제외 반경 60
- 그리기: 바닥 원반(청록 그라데이션) → 위로 갈수록 투명해지는 빛기둥(높이 60, `projectTall` 사용) → 주변 반짝임 4~6개
- `reduceMotion`일 때는 맥동과 반짝임을 멈추고 정적인 원반만

기존 `spores`(발광 홀씨)는 별 주변에서 밀도를 2배로 올립니다. 별에서 피어오르는 것처럼 보이게 하는 게 목적입니다.

**발견 요소로 쓰지 않습니다.** 랜드마크 6개 게이팅에 별을 끼워 넣으면 포탈 조건이 흐려집니다. 별은 순수한 풍경이고, 나중에 채집물로 쓸 여지만 남겨둡니다.

## 7. 작업 F — 초목 세분화와 나무 재작업

### 7-1. 초목을 군락으로

지금은 풀 다발 1400개가 월드 전체에 **균일하게** 뿌려져 있습니다. 그래서 어디를 봐도 똑같은 밀도입니다. 원작은 길가와 물가에 꽃이 뭉쳐 피고, 그 사이는 비어 있습니다.

종류를 다섯으로 나누고, 배치를 균일 난수에서 **군락 중심 + 주변 분산**으로 바꿉니다.

| 종류 | 개수 | 배치 |
| --- | --- | --- |
| 풀 다발 | 1100 | 기존 방식 유지 (바탕) |

### 7-2. 나무를 원작 크기와 형태로

원작 나무는 캐릭터의 서너 배 높이에, 잎이 **여러 겹의 비늘처럼** 겹쳐 있습니다(아티초크나 솔방울에 가까운 실루엣). 지금 우리 나무는 둥근 덩어리 세 겹이고 캐릭터보다 약간 큰 정도입니다.

| | 지금 | 바꿀 값 |
| --- | --- | --- |
| 반지름 | 19~32 | **28~46** |
| 수관 형태 | 원 3겹 | **잎비늘 층 4~5겹**, 각 층은 끝이 뾰족한 잎 6~8장 |
| 줄기 | 짧고 거의 안 보임 | 길이 1.4배, 밑동이 확실히 보이게 |
| 잎 색 | `#5aba7c` / `#4fa066` | **`#4aa86b` / `#3d8f59`** (한 단계 진하게) |
| 외곽선 | `#2d5f3f` | 유지, 두께만 반지름 비례로 소폭 증가 |

나무가 커지면 충돌 반지름도 커집니다. 현재 `solidRadius = radius * 0.5`인데, 나무가 46까지 커지면 반지름 23이 되어 길이 막힐 수 있습니다. **충돌 반지름은 `Math.min(radius * 0.5, 18)`로 상한을 둡니다.** 보이는 건 커지고 부딪히는 건 그대로인 편이 걷기에 낫습니다.

총 오브젝트 개수(240)는 유지합니다. 나무가 커진 만큼 겹침 판정(`overlapsExisting`)에서 자연스럽게 솎아집니다.

## 8. 작업 G — 생활의 흔적

에버그린의 공식 설명은 이렇습니다. *"주민들 대부분이 농사를 짓고 소를 치는, 작고 따스하고 평화롭고 사소한 별"*, *"작지만 사계절 마르지 않는 강가에서 소들이 풀을 뜯는 평화로운 광경"*.

지금 우리 맵에는 사람이 살았던 흔적이 하나도 없습니다. NPC를 만드는 건 큰 공사지만, **사람이 있었다는 흔적**은 소품만으로 충분히 만들 수 있습니다.

- **암소 3마리** — 광장 북동쪽 풀밭. 서 있다가 아주 가끔 고개를 숙이는 정도의 2프레임 애니메이션. 대화 불가, 충돌만 있음
- **목책 우리** — 암소 주변을 감싸는 낮은 울타리, 한쪽이 트여 있음
- **건초더미 2개, 여물통 1개** — 우리 안
- **작은 밭 한 뙈기** — 광장 서쪽. 이랑 5줄에 작물 싹
- **수레 1대** — 밭 옆에 세워둠
- **허수아비 1개** — 밭 가운데
- **빨래줄** — 데크 근처, 천 두어 장

전부 정적인 배경 오브젝트라 구현 부담이 작고, 화면에서 차지하는 인상은 큽니다.

## 10. 절대 건드리지 않는 것

로드맵 4에서 정한 것을 그대로 이어갑니다. 이번에는 지형에 높이가 생기기 때문에 오히려 더 중요합니다.

- `project()` / `projectTall()` / `PLANET_R` / `HORIZON_D` / `TILT` — **한 줄도 바꾸지 않습니다.** 높이는 이 함수들이 낸 좌표 위에 얹는 화면 오프셋일 뿐입니다
- 기존 랜드마크 6개의 좌표와 발견 로직
- 포탈 좌표(650, 1126)와 전환 로직, 6/6 게이팅
- fog of war와 탐험 격자 방식 — 원작에는 없는 우리 고유 메커닉이고, 의도적으로 유지합니다
- 구역별 난수 시드 분리 (`makeZone`의 `mulberry32`)

지형과 물은 **난수로 뿌리지 않고 좌표를 직접 박습니다.** 시드를 건드리면 기존 오브젝트 배치가 통째로 바뀌기 때문입니다. 손으로 놓은 지형 위에 기존 스캐터가 그대로 올라가는 구조여야 합니다.

## 11. 작업 순서와 의존관계

1. **A. 높이와 점프** — 나머지 전부가 여기에 올라탑니다. 단 하나 없이 빈 월드에서 점프와 계단 오르내림부터 확인합니다
2. **B. 물** — A의 `groundHeightAt`을 그대로 쓰므로 바로 이어서
3. **C. 맵 재구성** — A와 B가 있어야 광장을 지을 수 있습니다. 여기서 9장의 몬스터 공터도 같이 지정합니다
4. **D. 길** — C가 만든 통로 두 개에 맞춰 길을 다시 깝니다

## 14. 다음 결정이 필요한 것

맵1이 별내림 천문대 하나로 확정되면서 **기존 랜드마크 이름과 맵 이름이 어긋나는 곳**이 생겼습니다.

지금 맵1 안에는 `지붕 없는 동굴`이라는 랜드마크가 있는데, 이 이름은 맵8이 될 이름입니다. `석조 유적`과 `빛나는 결정`도 각각 겸손한 사원(맵2)과 붙박이 야영지(맵3)의 성격에 가깝습니다.

선택지는 셋입니다.

1. **그대로 둔다** — 랜드마크는 지명이 아니라 지형지물 이름일 뿐이라고 보는 입장
2. **천문대다운 이름으로 바꾼다** — 예: 지붕 없는 동굴 → `별이 떨어진 자리`, 빛나는 결정 → `별조각 바위`
3. **맵8을 만들 때 옮긴다** — 지금은 두고, 해당 맵을 만들 때 이름을 넘겨준다

기획상으로는 2번이 가장 깔끔하지만, 랜드마크 이름을 바꾸면 발견 토스트와 저장된 발견 상태가 함께 바뀌므로 결정이 필요합니다. **구현 시작 전에 정하고 갑니다.**
