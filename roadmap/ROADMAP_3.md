# 로드맵 3 — 완주 보상 · 포탈 · 두 번째 구역

**상태: 확정 · 작업 예정**
로드맵 2가 남긴 문제 — **"한 맵만 계속 돌아다니는 느낌"** — 을 푸는 단계입니다.

이번 단계가 만드는 흐름은 이렇습니다.

> 랜드마크 5개를 모두 찾는다 → **아스마라 초원의 전체 지도가 열린다** → 지금까지 안 가본 곳에 **포탈이 있다는 게 지도에 드러난다** → 거기까지 걸어간다 → **다음 구역으로 넘어간다**

---

## 0. 먼저 짚어둘 것: 이건 "다른 행성"이 아닙니다

포탈이 이어주는 곳은 **아스마라 안의 다른 구역**입니다. 다른 행성으로 나가는 게 아닙니다.

이게 중요한 이유는, 로드맵 1에서 확정한 **"한 행성(아스마라)만 완결시킨다"**는 원칙과 넥슨 IP 파트너 신청서에 적어둔 **"다른 행성으로의 이동은 제외"**라는 문장을 그대로 유지해야 하기 때문입니다. 이번 작업은 그 원칙을 깨는 게 아니라 오히려 기획서에 이미 적어둔 문장 — *"아스마라 한 행성 안을 초원·숲·샘물 지역 등 몇 개의 구역으로 나눠 구역마다 난이도가 다른 몬스터와 볼거리를 배치할 계획"* — 을 실제로 구현하는 작업입니다.

**따라서 기존 문서는 한 줄도 고칠 필요가 없습니다.** 포탈은 행성 간 이동 수단이 아니라 구역 관문입니다.

---

## A. 완주 보상 — 전체 지도 공개

랜드마크 5개를 전부 발견하면 그 구역의 지도가 통째로 열립니다.

### 이게 fog of war 원칙을 깨지 않는 이유

로드맵 2에서 **"지도는 절대 전체를 미리 보여주지 않는다"**를 핵심 원칙으로 못박았습니다. 그래서 이 기능이 그 원칙과 충돌하는지 따져봤습니다.

랜드마크 5개를 가장 효율적인 순서(샘물 → 바위산 → 거대 고목 → 빛나는 결정 → 석조 유적)로 최단 경로로 돌면, 도착 시점의 **탐험도는 72.8%**입니다. 실제로는 장애물을 피해 돌아가므로 이보다 높습니다.

즉 지도를 여는 시점에는 **이미 4분의 3을 직접 걸어서 밝혀둔 상태**입니다. 공짜로 주는 게 아니라 마지막 4분의 1을 완주 보상으로 채워주는 것이고, 원칙이 막으려던 것("걷기 전에 미리 보여주는 것")과는 정반대입니다. **보상은 원칙의 예외가 아니라 원칙의 결승선입니다.**

### 동작

- 5/5 달성 순간 격자를 전부 켜고 fog 캔버스를 구역 전체로 채웁니다 (탐험도 100%)
- 연출: 중심에서 바깥으로 퍼지는 원형 와이프, 약 0.8초
- 그 직후 자동으로 전체 지도가 열리면서 **포탈 아이콘이 처음 모습을 드러냅니다**
- 토스트: `아스마라 초원의 지도를 완성했습니다`

전체 지도가 자동으로 열리는 게 핵심입니다. 지도를 여는 보상과 다음 목적지를 알려주는 일이 한 동작으로 이어져야 "그래서 이제 뭘 하지?"가 생기지 않습니다.

## B. 포탈

### 위치 — 일부러 안 가본 곳에 둡니다

지도가 열리는 게 보상이 되려면, 열린 지도가 **몰랐던 것**을 알려줘야 합니다. 이미 아는 곳(스폰 지점 같은)에 포탈을 두면 지도를 여는 의미가 없습니다.

그래서 기존 랜드마크 5개의 방위를 확인해봤습니다.

| 랜드마크 | 방위 | 중심 거리 |
| --- | --- | --- |
| 거대 고목 | 5° (북) | 1154 |
| 샘물 지대 | 64° (동북동) | 255 |
| 바위산 | 80° (동) | 1197 |
| 석조 유적 | 231° (남서) | 1229 |
| 빛나는 결정 | 286° (서북서) | 1298 |

**80°에서 231° 사이, 즉 남동~남쪽 151° 구간이 통째로 비어 있습니다.** 랜드마크가 하나도 없어서 플레이어가 갈 이유가 없던 방향이고, 실제로 완주 시점에 안 밝혀진 27%가 대부분 여기입니다.

포탈은 그 한복판인 **방위 150°(남남동), 좌표 (650, 1126), 중심 거리 1300**에 둡니다. 지도가 열리는 순간 "저기 뭐가 있었네"가 되는 자리입니다.

### 비주얼과 상호작용

| 항목 | 사양 |
| --- | --- |
| 형태 | 돌 아치 + 안쪽에 천천히 회전하는 빛의 소용돌이. 높이 100 (지평선 너머에서도 보이는 랜드마크급) |
| 활성화 전 | 5/5 달성 전에는 아예 존재하지 않음 — 지도에도, 필드에도 안 보임 |
| 활성화 후 | 필드에 나타나고, 미니맵·전체 지도에 전용 아이콘으로 상시 표시 |
| 접근 | 반경 90 안에 들어오면 화면 하단에 프롬프트 — `E 다음 구역으로` (모바일은 탭 버튼) |
| 이동 | 프롬프트에서 키/탭을 눌러야 이동. 밟기만 해서는 안 넘어감 (실수 방지) |
| 전환 연출 | 0.5초 흰색 페이드 아웃 → 구역 교체 → 0.5초 페이드 인 |

높이 100을 준 이유는 로드맵 2에서 만든 원거리 가시성을 그대로 쓰기 위해서입니다. 지도에서 위치를 확인하고 그 방향으로 걷다 보면, 지평선 너머에서 아치 꼭대기가 먼저 떠오릅니다.

## C. 두 번째 구역 — 아스마라 · 이끼 숲

초원과 확실히 달라 보여야 "다른 데로 왔다"가 성립합니다.

| 항목 | 초원 (1구역) | 이끼 숲 (2구역) |
| --- | --- | --- |
| 지면 | 밝은 연두 | 짙은 청록, 그늘진 톤 |
| 하늘 | 맑은 파랑 | 옅은 안개빛 (연출용 배경색일 뿐, 시야 제한은 여전히 구체 투영으로만) |
| 나무 | 드문드문 240개 | 훨씬 촘촘하고 키가 큼 |
| 반경 | 1500 | **2200** |
| 랜드마크 | 5개 | 5개 (새 세트) |

반경을 2200으로 키우는 건 로드맵 2에서 지적해둔 문제 — *"이동 속도 200/초라 이론상 40초면 행성 전체를 볼 수 있다"* — 를 여기서부터 손보는 것입니다. 1구역은 이미 오브젝트 배치가 끝나 있으니 그대로 두고, 새로 만드는 구역부터 넉넉하게 잡습니다.

2구역의 랜드마크 5개를 다 찾으면 마찬가지로 지도가 열리고, **3구역으로 가는 자리에는 기존 `?` 표지판을 세워둡니다.** 3구역은 로드맵 4 이후입니다.

## D. 기술 설계 — 여기가 진짜 작업입니다

기능 자체보다 **구조 리팩터링이 이번 단계 작업량의 대부분**입니다. 솔직하게 적어둡니다.

### 지금 구조의 문제

현재 `asmara-exploration.html`은 월드가 통째로 모듈 스코프에 고정되어 있습니다.

```js
const obstacles = [];        // 파일 로드 시 1회 생성, 교체 불가
const grassTufts = [];
const landmarks = [...];
const explored = new Uint8Array(...);
const fogCanvas = ...;
const WORLD_RADIUS = 1500;   // 상수
```

`collides()`, `updateExploration()`, `drawMapCircle()` 같은 함수들이 이 전역을 직접 참조합니다. 이 상태로는 두 번째 구역을 만들 방법이 없습니다.

### 바꿀 구조

```js
function createZone(def) {
  const rand = mulberry32(def.seed);   // 구역마다 독립 시드
  // def: { id, name, radius, seed, palette, landmarks[], portals[] }
  return {
    def, obstacles, decorations, terrainPatches, grassTufts, spores,
    landmarks, explored, exploredCount, totalCells,
    fogCanvas, foundCount, mapRevealed: false
  };
}
const zones = { meadow: createZone(MEADOW), forest: createZone(FOREST) };
let zone = zones.meadow;
```

핵심 변경점 세 가지입니다.

**1. 난수 시드를 구역별로 분리합니다.** 지금은 전역 `rand()` 하나를 순차 소비하는 구조라, 구역을 하나 더 만드는 순간 소비 순서가 바뀌어 **1구역의 배치가 통째로 달라집니다.** 시드를 구역별로 떼어놔야 지금 배치가 그대로 보존됩니다. 이걸 놓치면 "왜 갑자기 초원이 달라졌지?"가 됩니다.

**2. 구역별 탐험 상태를 각자 보존합니다.** fog 캔버스, 격자, 발견 목록, 지도 공개 여부를 구역 객체 안에 둡니다. 1구역으로 돌아가면 밝혀둔 지도가 그대로 있어야 합니다.

**3. `WORLD_RADIUS` 상수를 `zone.def.radius`로 바꿉니다.** 충돌 경계, 미니맵 스케일, 격자 크기, 오브젝트 배치가 전부 이걸 참조하므로 한 군데라도 빠뜨리면 경계가 어긋납니다. 미니맵은 항상 "현재 구역 전체"를 원으로 보여주므로, 구역마다 반경이 달라도 화면상 크기는 같습니다.

### 구역 전환

```js
function enterZone(zoneId, spawn) {
  // 페이드 아웃 → zone 교체 → player 위치를 spawn으로 → 페이드 인
}
```

양방향이어야 합니다. **2구역에는 1구역으로 돌아오는 포탈을 반드시 둡니다.** 안 그러면 넘어간 순간 갇힙니다. 돌아오는 포탈은 2구역 스폰 지점 바로 옆에 두고, 1구역으로 돌아오면 원래 포탈 옆에 나타납니다.

## E. HUD와 지도

- HUD에 현재 구역 이름 추가 — `아스마라 · 초원` / `아스마라 · 이끼 숲`
- 거리 표시는 **현재 구역의 스폰 지점 기준**으로 계산 (구역이 바뀌면 기준도 바뀜)
- 발견 카운터는 현재 구역 기준 `발견 3/5`
- 전체 지도는 현재 구역만 보여줍니다. 구역 전체를 한눈에 보는 상위 지도는 구역이 3개 이상 생기는 로드맵 4 이후에 검토합니다

## F. 작업 순서

1. **`createZone()` 구조로 리팩터링** — 기존 초원을 1구역으로 분리, 시드 분리로 현재 배치 보존 확인
2. 구역별 fog·격자·발견 상태 분리
3. 5/5 달성 시 지도 공개 + 원형 와이프 연출
4. 포탈 오브젝트 (아치 + 회전 소용돌이) 배치 및 렌더링
5. 포탈 접근 프롬프트 + E키/탭 상호작용
6. `enterZone()` + 페이드 전환
7. 2구역(이끼 숲) 정의 — 팔레트, 밀도, 반경 2200, 랜드마크 5종
8. 양방향 포탈 연결 + 3구역 자리에 `?` 표지판
9. HUD 구역 이름 표시
10. Playwright 검증 후 배포

**1번이 끝난 시점에 반드시 1구역이 리팩터링 전과 똑같이 보이는지 확인하고 넘어갑니다.** 여기서 배치가 틀어지면 이후 작업 내내 원인을 못 찾습니다.

## G. 완료 기준

- [ ] 리팩터링 후에도 1구역 지형·오브젝트 배치가 이전과 동일
- [ ] 랜드마크 5/5 달성 시 지도가 열리고 탐험도 100%가 되며 와이프 연출이 재생됨
- [ ] 달성 직후 전체 지도가 자동으로 열리고 포탈 아이콘이 보임
- [ ] 5/5 전에는 포탈이 필드에도 지도에도 존재하지 않음
- [ ] 포탈 방향으로 걸어가면 지평선 너머에서 아치 꼭대기가 먼저 보임
- [ ] 포탈 접근 시 프롬프트가 뜨고, 키/탭을 눌러야만 이동
- [ ] 2구역이 초원과 확연히 다르게 보이고, 반경 2200이 경계·미니맵에 정확히 반영됨
- [ ] 2구역에서 1구역으로 돌아올 수 있고, 1구역의 탐험 기록·발견 상태가 그대로 보존됨
- [ ] 데스크톱·모바일 60fps 유지, 콘솔 에러 없음

## H. 이번에 하지 않는 것

전투, 성장(레벨·경험치), 저장(localStorage), 3구역, 구역 전체를 한눈에 보는 상위 지도는 **로드맵 4 이후**로 넘깁니다.

특히 **저장**은 이번 단계가 끝나면 잃을 게 두 구역치로 늘어나므로 다음 순번 1순위 후보입니다.
