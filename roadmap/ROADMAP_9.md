## 1. 작업 A — 규격 동결

로드맵 6에서 쓴 `web/assets/README.md`는 로드맵 7 지도 기준입니다. 로드맵 8에서 지도가 1.45배 커지고 구조물이 늘었으니 표를 다시 씁니다.

- **크기표 갱신**: 판의 유닛 크기는 그대로지만(캐릭터 키 ≈ 1.7), "여러 개 흩어짐" 항목의 개수와 간격이 달라졌다 — 나무 63, 덤불 12, 꽃 14, 버섯 11, 갈대 19, 돌 10, 말뚝은 간선 8구간. 로드맵 8의 좌표표(§1-2)와 전경도 이름표를 참고 그림으로 넣는다.
- **새 슬롯 등록**: 지금은 캔버스 그림으로만 그리는 것들에 `spriteTex(w, h, draw, '이름')` 이름을 붙여 PNG로 바꿔 끼울 수 있게 한다 — `stairs`(돌계단 한 단 윗면·옆면), `deck`(팔각 데크 바닥·난간), `bridge_plank`(판자 한 장), `crater_rock`(크레이터 둘레 바위), `pedestal`(선돌 고리 받침대 — 지금은 `star` 큰 판 재사용), `portal`(열린 포탈 원반·고리), `sign_field`(착륙 들판 표지), `tile_sand`(모래길), `tile_cliff`(절벽면). 각각 캔버스 그림을 기본값으로 두고 `manifest.json`에 이름을 추가한다.
- **바꿔 끼우기 흐름 점검**: PNG가 깨졌거나 비율이 다를 때 콘솔 경고 + `?fps` 줄에 "에셋 n/35 · 비율 틀림: tree_1" 표시. `manifest.json`의 `version`을 올리는 걸 잊어도 되게, 파일 이름 뒤에 `?v=<manifest version>`을 붙이는 지금 방식에 더해 **파일 크기·수정 시각으로 캐시를 깨는 선택지**를 검토한다(GitHub Pages는 ETag를 주므로 대개 불필요 — 확인 뒤 결정).
- **원작 추출 에셋 적용 정리표**(프로젝트 문서 `원작추출에셋_적용정리표`)는 참고만 하고, 저장소엔 넣지 않는다.

## 2. 작업 B — 지도 마무리

로드맵 8 추기 #5·#6에서 미니맵과 M 지도는 파스텔 양피지 그림 지도가 되었습니다. 남은 것:

- **미니맵 테두리**: 금색 고리 대신 양피지 지도와 같은 결의 **헤진 둥근 종이 + 나무 테**로. 북쪽 글자 N은 작은 나침반 바늘로.
- **확대 단계**: 미니맵 반지름 ±8.5°(설계)를 기본으로, 마우스 휠·`[` `]`로 ±5°/±8.5°/±13° 세 단계. 저장에 기억.
- **M 지도 이름표**: 지금은 HTML 이름표(흰 상자)라 종이 위에 떠 보인다. 캔버스에 **갈색 손글씨체 + 밑줄 장식**으로 직접 쓰고, 겹치는 자리는 살짝 밀어낸다. 글꼴은 Gowun Dodum 그대로, 색은 테두리 색(92,62,32).
- **표식**: 추적 중인 퀘스트 목표(NPC 또는 받침대)를 **노란 깃발**, 포탈이 열리면 겸손한 사원 방향에 **초록 화살표 + 점선 길**. 플레이어 표식은 분홍 삼각형 유지.
- **안 가 본 곳 가리기(선택)**: 원작엔 없지만 탐험 맛을 위해, M 지도에서 아직 가까이 가지 않은 구역을 **옅은 안개로 덮고** 지나간 곳부터 걷히게 한다. 설계 좌표 2° 격자로 방문 여부를 저장(`map.seen`)에 넣는다. 기본은 끔 — §11에서 결정.
- **전경도(M M)**: 옛 2D판의 그림책풍 캔버스를 그대로 쓰고 있다. 섬·구름·연결선 톤을 양피지 지도와 맞추고(종이색·갈색 선), 별내림 천문대 섬에는 §2의 그림 지도 축소판을 그려 넣는다.

## 3. 작업 C — 소리

지금 게임엔 소리가 하나도 없습니다. **배경음악 + 효과음**을 한 체계로 넣습니다.

- **폴더·목록**: `web/audio/`에 `manifest.json`(이름 → 파일, 음량, 루프 여부)과 `README.md`(규격·출처·라이선스). 포맷은 **OGG(Vorbis) 우선, MP3 대체**(사파리). 길이·용량 목표: BGM 1곡 1\~2분 루프 ≤ 1.5MB, 효과음 ≤ 50KB.
- **재생 체계**: Web Audio API 하나로 — BGM은 `AudioBufferSourceNode` 루프 + `GainNode`로 서서히 바꿈(cross-fade 1.2초), 효과음은 짧은 버퍼를 동시에 여러 개. 브라우저 **자동재생 정책** 때문에 첫 키 입력·클릭·시작 화면 버튼에서 `AudioContext.resume()`; 그전엔 "소리를 켜려면 아무 키나" 안내 한 줄.
- **곡 구성(별내림 천문대)**: ① 들판·초원 기본 테마(잔잔한 루프) ② 전투 변주(몬스터 구역 안에서 적이 쫓아오면 전환, 3초 뒤 복귀) ③ 착륙 컷신(8초, 비행정 하강에 맞춰) ④ 포탈 진입 짧은 전환음 ⑤ 시작 화면. 곡은 **직접 만든 것 또는 CC0/CC-BY 음원**만 — 원작 BGM은 쓰지 않는다(§11에서 출처 결정).
- **효과음 16종**: 걷기(풀·모래·판자·물 4종), 점프·착지, 수영, 공격 휘두름, 타격, 피격, 슬라임 처치, 가시 슬라임 돌진 예고, 아이템 습득, 채집 완료, 레벨업, 퀘스트 수락·완료, 포탈, UI 열기·닫기, 저장됨.
- **설정은 ESC 설정 화면의 소리 탭**(§12): 전체·BGM·효과음 음량(0\~100, 기본 80·60·80), 음소거 토글(단축키 **N**), `ep.settings.v1`에 기억. 터치 기기에선 HUD 모서리에 스피커 버튼. 추기 #1에서 "설정 창(O)"을 여기로 흡수.
- **상태 연동**: 지도·창이 열려 게임이 멈추면 BGM 음량을 절반으로, 전투 변주는 `inZone`과 추적 중 적 수로 판단.

## 4. 작업 D — 초목 밀도·인스턴싱·성능 문턱

로드맵 7 추기 #6에서 넘어온 핵심입니다. 지도가 1.45배 커져서 지금 그림이 성글어 보이고(원작 지도는 가장자리가 나무로 빽빽), 추기 #4 뒤 관측소에서 삼각형 105만·드로우콜 523으로 늘었습니다.

- **InstancedMesh 전환**: 말뚝(지금도 인스턴싱)에 이어 **풀 포기(새 그림 `grass_tuft`, 3,000\~6,000개)·꽃·갈대·돌·버섯**을 종류별 InstancedMesh 하나로. 빌보드 회전은 셰이더에서(카메라 방향은 고정이라 인스턴스마다 기울기만).
- **나무 63 → 150+**: 로드맵 8 §6의 "가장자리 빽빽" 밀도로 — 바위벽 안쪽 띠(설계 1.5°)에 2\~3겹, 초원·크레이터·길·야영지 안은 비움. 나무는 그림자가 있어 인스턴싱 대상이지만 `castShadow`는 플레이어 가까운 40그루만.
- **지형 패치 성글게**: 고해상 패치(0.15° 간격, 8×12 타일)에서 플레이어로부터 먼 타일은 0.3° 간격 사본으로 바꿔 그린다(두 벌 만들어 거리로 교체). 수면 패치도 같이.
- **성능 문턱 P**(로드맵 7 추기 #6에서 이월): 크롬 기준 **1280×720 '높음'에서 드로우콜 ≤ 300·삼각형 ≤ 50만·프레임 16.7ms 이내**, '낮음'에서 노트북 내장 그래픽 30fps. 게시마다 `?fps` 표본 4곳(착륙 들판·다리 가운데·야영지·관측소)을 추기에 적는다.

## 5. 작업 E — 애니메이션

- **캐릭터**: `char_sheet.png`(정면·등·옆)를 걷기 4프레임 × 방향 3 + 공격 3프레임 + 점프·수영 각 2프레임 시트로 늘리고, 코드는 프레임 번호만 UV로 고른다. PNG가 옛 시트(프레임 1장)면 지금처럼 멈춘 그림.
- **몬스터**: 슬라임은 지금 코드로 통통 튀는 비례 변형 — 여기에 **눈 깜빡임·착지 찌그러짐 2프레임**, 가시 슬라임은 돌진 예고 때 **가시 세움 프레임**.
- **NPC**: 숨쉬기(세로 1\~2% 흔들림)와 말 걸 때 고개 끄덕.
- **환경**: 나무 흔들림(지금 있음)에 **풀 포기 바람 결**(인스턴스 셰이더에 시간 항), 물 반짝임 띠, 포탈 소용돌이(지금 있음), 별 조각 빛기둥 맥동(지금 있음).

## 6. 작업 F — 원경·하늘·빛

- **지평선 너머**: 놀이 구역 바위벽 바깥은 지금 민둥 구면이다. 바위벽 바깥 띠에 **먼 산 실루엣 판**(큰 빌보드 3\~4장, 안개 색에 녹아듦)과 **떠 있는 작은 섬 2\~3개**(원작 느낌) — 섬은 전경도의 다음 지역을 암시하는 위치(북동쪽 겸손한 사원 쪽).
- **구름**: 지금의 구름 판에 더해 그림자가 땅을 지나가는 **구름 그림자 층**(지형 셰이더에 노이즈 곱).
- **시간대**: 낮 고정을 기본으로 두되, 설정에서 **저녁 노을**(주황 하늘·긴 그림자·등불 켜짐)을 고를 수 있게. 자동 시간 흐름은 넣지 않는다(지도 색과 그림이 낮 기준).
- **안개 색**: 하늘·안개·멀리 산 색을 한 팔레트에서 뽑아 §1의 색표에 추가.

## 7. 작업 G — 화면 구성 통일

- HUD 오브·스킬 바·퀘스트 창·가방·스킬 창·기록 창·시작 화면의 테두리·바탕을 **양피지 + 나무 테** 한 세트로(지도와 같은 결). 아이콘(포션·이슬·젤리·가시·별씨앗·스킬 3종)은 PNG 슬롯으로 등록해 바꿔 끼울 수 있게.

## 12. 작업 S — 설정 화면(ESC) 설계 (추기 #1)

### 12-1. 여닫기와 규칙

- **ESC 한 번**: 지도·창(가방·스킬·퀘스트·기록)·대화·채팅이 열려 있으면 지금처럼 **그것만 닫는다**. 아무것도 안 열려 있으면 **설정 화면**을 연다. 설정 화면이 열려 있을 때 ESC는 닫기. 시작 화면·컷신·포탈 이동 중엔 열리지 않는다(컷신은 Space로 건너뛰기 그대로).
- 열려 있는 동안 게임은 **멈춘다**(지도와 같은 `gate`). 키 입력은 설정 화면이 가져가고, 닫으면 눌린 키 상태를 비운다(`keys.clear()`).
- 터치 기기: HUD 오른쪽 위(미니맵 아래)에 **톱니 버튼**. 설정 화면 안은 손가락으로 쓸 수 있게 슬라이더·버튼을 44px 이상으로.
- 모양: 양피지 + 나무 테(작업 G의 세트를 먼저 여기에 적용). 왼쪽 세로 탭 5개, 오른쪽 내용, 아래 줄에 **[기본값 복원] [닫기]**. 탭은 `1`\~`5` 숫자키나 `Q`/`E`로 넘길 수 있다(설정 화면 안에서만).

### 12-2. 탭 구성

| 탭 | 항목 | 비고 |
| --- | --- | --- |
| **조작** | 동작표(12-3), 키 다시 매기기, 보조 키, 이동 방식(WASD / 방향키 둘 다 기본), 키 안내 보기(H와 같은 내용) | 로드맵 7 H의 키 안내 팝업은 이 탭을 여는 단축키로 남긴다 |
| **소리** | 전체 음량·BGM·효과음 슬라이더(0\~100), 음소거(N), 효과음 미리 듣기 버튼, "소리를 켜려면 아무 키나" 상태 표시 | 작업 C 전엔 슬라이더와 저장만 동작하고 들리는 건 없음 |
| **화면** | 화질(자동·높음·중간·낮음·최소 — 지금의 Q 순환을 선택지로), 피해 숫자 표시, 화면 흔들림, FPS 표시(`?fps`와 같은 줄), 시간대(작업 F 뒤: 낮·저녁) | 화질 자동은 지금처럼 프레임 간격으로 오르내림 |

### 12-3. 키 설정

**동작표** — 코드의 입력 처리를 "키 글자"가 아니라 **동작 이름**으로 바꾼다. 지금 `keys.has('w')`·`k === 'i'`처럼 흩어진 비교를 `isDown('moveUp')`·`onAction('inventory')`로 모은다.

| 동작 id | 이름 | 기본 키 | 보조 키 | 바꿀 수 있나 |
| --- | --- | --- | --- | --- |
| moveUp / moveDown / moveLeft / moveRight | 이동 | W / S / A / D | ↑ / ↓ / ← / → | ○ |
| jump | 점프(2단) · 컷신 건너뛰기 · 대화 넘기기 | Space | — | ○ |
| attack | 공격 | Z | — | ○ |
| skill1 / skill2 / skill3 | 스킬 슬롯 | X / C / V | — | ○ |
| interact | 대화·상호작용(길게: 채집) | F | — | ○ |
| target | 대상 바꾸기 | Tab | — | ○ |
| potionHp / potionMp / dew | 포션·이슬 | 1 / 2 / 3 | — | ○ |
| inventory / skills / quests / character | 창 | I / K / J / P | — | ○ |
| map | 지도(미니맵 → M 지도 → 전경도) | M | — | ○ |
| chat | 채팅 | Enter | — | ○ |
| keyGuide | 키 안내(조작 탭 열기) | H | — | ○ |
| quality | 화질 순환 | Q | — | ○ |
| mute | 음소거 | N | — | ○ |
| settings | 설정 열기/닫기 | Escape | — | ✕ (고정) |

- **키 식별은 `e.code`**(물리 키: `KeyW`, `Space`, `ArrowUp`, `Digit1`)로 하고, 보여 줄 때는 `e.key`를 대문자로(한글 자판에서도 같은 자리). 지금 코드는 `e.key.toLowerCase()`라 한/영 전환 상태에 따라 안 먹는 일이 있었는데, `e.code`로 바꾸면 사라진다.
- **다시 매기기 흐름**: 동작 줄의 키 칸을 누르면 "키를 누르세요…"로 바뀌고 다음 `keydown`을 받는다. ESC는 취소, Backspace는 보조 키 비우기. 받은 키가 **다른 동작에 이미 있으면 서로 맞바꾼다**(그 동작의 칸이 잠깐 노랗게 깜빡여 알려 줌). 고정 키(Escape)와 브라우저 예약 키(F5·F11·F12)는 거절하고 한 줄 안내.
- **한 동작에 주 키 + 보조 키 1개**. 이동 4개는 보조 키가 방향키로 미리 채워져 있다.
- **안내 글 자동 갱신**: HUD 스킬 슬롯 글자(X·C·V), 상단 키 안내 줄(WASD 이동 · Space 점프 …), 상호작용 말풍선(`F 대화하기`), 대화 "Space로 넘기기", 키 안내 팝업(H), 시작 화면의 1·2 — 전부 `keyLabel('interact')` 같은 함수로 뽑아 쓴다. 키를 바꾸면 그 자리에서 글이 바뀐다.
- **기본값 복원**은 조작 탭 안에서는 키만, 아래 줄 버튼은 탭 전체.

### 12-4. 소리 탭(작업 C와의 접점)

- 슬라이더 3개(전체·BGM·효과음)는 **GainNode 3개**에 바로 걸린다: `master → bgmGain / sfxGain`. 작업 C 전에는 노드만 있고 소리 파일이 없다 — 슬라이더가 움직이고 값이 저장되는 것까지만 S에서 끝낸다.
- 음소거는 `master.gain`을 0으로(값은 따로 기억해 되돌림). N 키와 탭의 토글이 같은 상태를 본다.
- "효과음 미리 듣기"는 C에서 `ui_click` 효과음이 생기면 그것을 재생, 그전엔 짧은 합성음(오실레이터 0.08초)으로.
- 브라우저 자동재생 정책: 설정 화면 자체가 사용자 입력으로 열리므로 여기서 `AudioContext.resume()`을 걸어도 된다. 상태 줄에 "소리 켜짐 / 아무 키나 누르면 켜짐"을 표시.

### 12-5. 저장(`ep.settings.v1`)

```json
{ "v": 1,
  "binds": { "moveUp": ["KeyW", "ArrowUp"], "attack": ["KeyZ", null], "...": "..." },
  "audio": { "master": 80, "bgm": 60, "sfx": 80, "mute": false },
  "display": { "quality": "auto", "dmgNum": true, "shake": true, "fps": false, "time": "day" },
  "map": { "mini": true, "zoom": 1, "fog": false, "labels": true } }
```

- 저장 파일(`ep.save.v1`)과 **분리**: 새로 시작·저장 삭제에도 설정은 남고, 브라우저(기기)마다 따로 간다. 읽을 때 모르는 키·틀린 값은 기본값으로 메운다(버전 `v`가 오르면 옮겨 적는 함수 하나).
- 쓰기는 값이 바뀔 때마다 바로(디바운스 300ms). 설정 화면을 닫을 때 "저장됨" 토스트는 띄우지 않는다(게임 저장과 헷갈림).
- 디버그 훅: `__dbg.settings`, `__dbg.rebind(action, code)`, `__dbg.openSettings()`.

### 12-6. 구현 순서와 검증

- **S1** 설정 저장소 + ESC 여닫기 + 창 틀 + 게임 탭 → **S2** 동작표로 입력 처리 리팩터 + 조작 탭(다시 매기기·안내 글 갱신) → **S3** 소리 탭(GainNode·슬라이더·N) → **S4** 화면·지도 탭(화질 선택·FPS·미니맵 표시). 각각 한 커밋.
- 검증(Playwright): ESC 규칙(창 열림 → 닫기만 / 없음 → 설정), `rebind('attack','KeyX')` 뒤 X로 공격·Z로는 안 됨·HUD 글자 X, 충돌 맞바꿈, 새로고침 뒤 복원, 기본값 복원, 슬라이더 → `gain.value` 반영, N 토글, 한/영 전환 상태에서도 `e.code`로 동작. 로드맵 7 G·H 스위트와 로드맵 8 스위트는 키 입력을 `press('w')`로 흉내 내므로 훅을 동작 id로도 받게 보강한다.

## 13. 작업 W — 물 연출 (로드맵 8 추기 #7\~#12에서 옮김, 추기 #2)

아래는 로드맵 8에 적혀 있던 추기 여섯 개를 번호·본문 그대로 옮긴 것이다. 작업은 전부 끝났고, 이 로드맵의 다른 작업(특히 A의 규격·B의 그림 지도 물색·D의 수면 패치)이 이 결과 위에서 이어진다.

> 따라 바꾼 것: 수면 메시 정점 높이·물가 포말 값, 지형 물바닥 색, 수영/얕은 물 판정·수영 높이·캐릭터 자르기 평면, 카메라 최저 높이, 슬라임 이동 가능 판정, 저장 불러오기 안전 판정, 말뚝 배치, 그림 지도의 물·얕은 물 판정을 전부 `WATER` 대신 `waterAt()` 기준으로. 수위가 오르며 잠기는 소품 보정 — 샘물 안에 있던 이슬 2곳(1.9,14.2 / 3.7,12.4 → 0.95,15.5 / 4.3,11.45, 둘레 턱 위), 추기 #11로 섬 비탈이 물에 잠기면서 함께 잠겼던 섬 갈대 2곳(4.0,24.6 / 3.6,21.6 → 3.55,24.2 / 3.3,22.0, 섬 턱 위), 수문장 벨라는 물가에서 한 발 물러섬(4.9,14.5 → 5.2,14.65). 폭포 물보라 판은 호수 바닥(-4.15)에 놓여 원래도 물에 가려져 있었던 것을 이번에 발견해, 밑단이 새 수면 0.4 아래에 걸치도록 올렸다.
>
> 검증(Playwright, 콘솔 에러 0): 놀이 구역 전체(0.1° 격자)에서 "옛 수면보다 높던 땅이 새 수면 아래로 잠긴 곳"을 호수·샘물 바깥에서 찾아 0곳 확인, 전환대 최소 여유(지형−수면)는 샘물 둘레 턱의 0.15. 호수 남쪽 단면(물가 0.02 / 수면 -0.45), 샘물 남북 단면(둘레 0.46\~0.47 / 수면 0.3 / 바닥 -0.45) 확인. 호수 한가운데 수영(z -0.8)→남쪽 물가로 헤엄쳐 48프레임 만에 상륙, 다리 위(z 0.35) 수영 아님, 샘물 한가운데 얕은 물(걷기)→북쪽으로 걸어 나옴, 섬 위 정상, 이슬 3곳·벨라 근접 판정 정상. 스크린샷으로 다리 진입부·다리 위(수면이 판자 바로 밑)·샘물 근경/남쪽 원경(둘레 경사면이 거의 안 보임)·섬·폭포 발치·그림 지도(호수·샘물 물색)까지 육안 확인.
