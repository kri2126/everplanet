# 로드맵 4 — 1구역(초원) 세분화

**상태: 설계 단계 (구현 전)**
"한 맵만 계속 돌아다니는 느낌"을 포탈로 한 번 풀었지만(로드맵 3), 정작 **1구역(아스마라 초원) 자체는 여전히 균질한 하나의 들판**입니다. 나무·바위 240개가 전역에 고르게 뿌려져 있을 뿐, 어디를 걸어도 풍경이 똑같습니다. 이번 로드맵은 그 안을 몇 개의 구별되는 구역으로 나누는 작업입니다.

사실 이건 새로운 아이디어가 아니라, 최초 기획 문서(`DESIGN_DOC.md`)에 처음부터 적혀 있던 문장을 이제야 구현하는 것입니다.

> *"아스마라 한 행성 안을 초원·숲·샘물 지역 등 몇 개의 구역으로 나눠 구역마다 난이도가 다른 몬스터와 볼거리를 배치할 계획"*

---

## 1. 원작 조사 — 참고한 것과 참고하지 않은 것

### 1-1. "아스마라"는 참고 대상이 아닙니다

나무위키에서 원작 에버플래닛의 실제 "아스마라" 행성을 찾아보면, 우리 프로토타입과는 완전히 다른 곳입니다.

| 항목 | 원작 아스마라 | 우리 프로토타입 "아스마라" |
| --- | --- | --- |
| 포지션 | 중후반 행성 (적정레벨 35~48) | 시작 행성 |
| 테마 | 사막 — 카르발라·아루샤 두 왕국의 영토 분쟁 | 초원/숲, 평화로운 동화풍 |
| 지역 수 | 25개 지역 (모래 서클, 고대왕국 유적, 백사산, 살라핫 오아시스 등) | 아직 1개 (분화 전) |

이 차이는 실수가 아니라 우리 기획 문서 2장에 명시된 **의도적 재해석**입니다("아스마라: 초반 행성. 평화로운 초원/숲 테마"). 그래서 이번 조사는 "아스마라"가 아니라, 원작에서 실제로 **처음 시작하는 행성**을 참고 대상으로 삼았습니다.

### 1-2. 실제 참고 대상 — 에버그린 (원작 튜토리얼 위성)

원작에서 새 캐릭터가 맨 처음 도착하는 곳은 이타카 주변을 도는 위성 **에버그린**입니다. "여행자의 별"이라 불리며, 농사·목축이 주요 산업인 평화로운 튜토리얼 지역입니다 — 테마 자체가 우리가 재해석한 "아스마라"와 거의 일치합니다.

에버그린은 하나의 열린 들판이 아니라 **8개의 이름 붙은 지역**으로 나뉘어 있고, 적정레벨 순서로 자연스럽게 이어집니다.

| 지역명 | 적정레벨 | 특징 |
| --- | --- | --- |
| 별내림 천문대 | 1~2 | 첫 도착지, 파란 슬라임 |
| 겸손한 사원 | 1~3 | 옛 사원, 도둑 슬라임 |
| 붙박이 야영지 | - | 첫 번째 마을 (상점·요리) |
| 늘 푸른 강가 | 3~5 | 강이 맵을 관통 |
| 뮤렌 습지대 | 6~8 | 세계수 샘물로 생긴 습지, 유일한 선공격 몬스터 |
| 해안 벌목지 | 8~9 | 간척 사업 중, 환경 오염 연출 |
| 에버그린 항구 | - | 1차 전직, 던전 입구 |
| 지붕 없는 동굴 | 9↑ | 유일한 던전 |

*(출처: [에버그린(에버플래닛) - 나무위키](https://namu.wiki/w/%EC%97%90%EB%B2%84%EA%B7%B8%EB%A6%B0(%EC%97%90%EB%B2%84%ED%94%8C%EB%9E%98%EB%8B%9B)))*

### 1-3. 여기서 가져올 설계 원칙

에버그린 구조에서 우리 프로토타입에 그대로 옮길 수 있는 것과, 옮길 수 없는 것을 구분했습니다.

**가져올 것:**
- **각 지역이 이름과 뚜렷한 테마(지형·색감)를 갖는다.** 강가는 강가답게, 습지는 습지답게 보여야 한다.
- **지역마다 성격이 다르다.** 첫 지역(별내림 천문대)은 순한 몬스터, 습지는 유일하게 선공격 몬스터 — 난이도/분위기가 지역마다 차등.
- **경유지 성격의 지역(붙박이 야영지, 에버그린 항구)이 따로 있다.** 전부 사냥터가 아니라, 쉬어가는 지점이 있다.

**가져오지 않을 것 (이미 확정된 우리 설계 원칙과 충돌):**
- **씬 전환은 안 씁니다.** 에버그린은 지역마다 사실상 별도 맵(로딩)일 가능성이 높지만, 로드맵 1에서 확정한 **정구형 투영 오픈월드**는 그대로 유지합니다. 지역 구분은 로딩이 아니라 **한 들판 안에서 걸어가면 풍경이 바뀌는 방식**으로 구현합니다.
- **전투/몬스터는 이번에 안 넣습니다.** 로드맵 4는 순수하게 지형·테마 분화만 다루고, 몬스터 배치는 다음 로드맵(전투 시스템과 함께)으로 넘깁니다. 다만 지역 경계를 지금 잡아두면 나중에 지역별 몬스터를 끼워 넣기가 훨씬 쉬워집니다.

## 2. 왜 "동심원"이 아니라 "방위 구간"인가

세분화 방법은 두 가지를 검토했습니다.

**(A) 중심에서의 거리로 나누기** (동심원): 중심 0~500은 초원, 500~1000은 숲, 이런 식. 구현은 쉽지만 문제가 있습니다 — 로드맵 2에서 이미 5개 랜드마크를 **모든 방위에 흩어 배치**해뒀습니다(거대 고목 5°, 샘물 64°, 바위산 80°, 석조 유적 231°, 빛나는 결정 286°). 동심원으로 나누면 서로 다른 테마의 랜드마크가 같은 링 안에 섞여버립니다.

**(B) 중심에서의 방위(각도)로 나누기** (파이 조각): 이미 배치된 5개 랜드마크가 **훌륭한 앵커** 역할을 합니다. 각 랜드마크가 자기 방향 전체의 테마를 대표하도록 나누면, 기존 배치를 그대로 살리면서 테마만 입힐 수 있습니다.

**(B)를 채택합니다.** 로드맵 2·3에서 이미 계산해둔 랜드마크 방위를 그대로 재사용할 수 있고, 새로 배치를 갈아엎을 필요가 없습니다.

## 3. 구역 설계

기존 5개 랜드마크 방위(로드맵 3 기준)를 정렬하면 다음과 같습니다.

| 랜드마크 | 방위 |
| --- | --- |
| 거대 고목 | 5° |
| 샘물 지대 | 64° |
| 바위산 | 80° |
| 석조 유적 | 231° |
| 빛나는 결정 | 286° |

샘물(64°)과 바위산(80°)은 겨우 16° 차이라 따로 쪼개면 걸으면서 체감이 안 됩니다. 반대로 바위산(80°)과 석조 유적(231°) 사이 151°는 로드맵 3에서 이미 "완전히 비어 있다"고 확인했고, 그 한복판(150°)에 **포탈**을 심어뒀습니다 — 이 구간은 그 자체로 하나의 독립된 테마를 줄 가치가 있습니다.

이걸 반영해 **5개 구역**으로 나눕니다.

| 구역 | 방위 범위 | 앵커 | 테마 |
| --- | --- | --- | --- |
| ① 시작 초원 | 스폰 반경 ~300 (전 방위, 중심 오버레이) | 스폰 지점 (0, 60) | 지금과 같은 밝은 파스텔 초원. 첫인상은 안전하고 평온하게 유지 |
| ② 오래된 숲 | 320°~40° | 거대 고목 | 나무 밀도↑, 키 큰 나무 비중↑, 그늘진 톤. 에버그린의 "겸손한 사원" 같은 고요한 분위기 |
| ③ 샘물가 구릉 | 40°~145° | 샘물 지대 + 바위산 | 목가적인 샘물 초원에서 동쪽으로 갈수록 완만히 바위 지대로. 나무:바위 비율이 동쪽으로 갈수록 역전 |
| ④ 폐허 관문 | 145°~250° | 석조 유적 + 포탈 | 황무지 톤(갈색·마른 풀), 장식 최소화. 무너진 기둥과 포탈이 있는 방향 — "다음 구역으로 이어지는 길목"이라는 인상을 시각적으로도 주는 구간 |
| ⑤ 결정 황혼지대 | 250°~320° | 빛나는 결정 | 어스름한 보라/남색 톤, 기존 `spores`(발광 홀씨) 밀도를 이 구간에 집중 배치해 신비로운 인상 강화 |

에버그린의 "붙박이 야영지"(경유지 마을) 역할은 ①시작 초원이 맡습니다 — 몬스터가 없는 이번 프로토타입 특성상 별도 마을을 만들 실익이 적어, 스폰 지점 자체를 안전지대 성격으로 유지하는 선에서 그칩니다.

## 4. 기술 설계

### 4-1. 핵심 원칙 — 씬 분할이 아니라 "채색"

구역은 별도 데이터 구조(로드맵 3의 `zones`처럼 씬을 통째로 바꾸는 것)가 아니라, **기존 `makeZone()` 안에서 생성되는 오브젝트 하나하나에 "어느 구역 소속인지"를 태깅**하는 방식으로 구현합니다. 걸어서 넘어가는 순간 전환 연출이 생기면 안 되고(포탈과 혼동됨), 그냥 자연스럽게 풍경이 바뀌어야 하기 때문입니다.

```js
function bearingOf(x, y) {
  let a = Math.atan2(x, -y) * 180 / Math.PI; // 기존 bearingLabel()과 동일한 기준
  if (a < 0) a += 360;
  return a;
}

const REGIONS = [
  { id: 'forest',  name: '오래된 숲',      from: 320, to: 40,  treeRatio: 0.85, densityMul: 1.3, groundTint: '#3f7a55' },
  { id: 'spring',  name: '샘물가 구릉',    from: 40,  to: 145, treeRatio: 0.55, densityMul: 1.0, groundTint: '#6fbf72' },
  { id: 'ruins',   name: '폐허 관문',      from: 145, to: 250, treeRatio: 0.30, densityMul: 0.7, groundTint: '#a99570' },
  { id: 'crystal', name: '결정 황혼지대',  from: 250, to: 320, treeRatio: 0.45, densityMul: 0.9, groundTint: '#5a5a92' },
];
function regionAt(x, y) {
  if (Math.hypot(x, y) < 300) return null; // 시작 초원 — 구역 없음(기본 톤 유지)
  const b = bearingOf(x, y);
  return REGIONS.find(r => r.from < r.to ? (b >= r.from && b < r.to) : (b >= r.from || b < r.to)) || null;
}
```

### 4-2. 지형 색감 — `terrainPatches` 확장

현재 `terrainPatches`는 옅은 흰색 하이라이트 얼룩일 뿐, 지역 색을 표현하지 않습니다(`rgba(255,255,255,0.10)` 고정, `drawTerrain` 관련 렌더링 485~493번째 줄, 1332~1338번째 줄 참고). 여기에 `regionAt()`으로 계산한 `groundTint`를 섞어, 지역 안에서 생성되는 patch는 흰색 대신 그 지역 색을 옅게 깔도록 바꿉니다. 패치는 기존처럼 폭 140~230 크기로 흩어져 있으므로, 걸어가면서 하나씩 시야에 들어오는 자연스러운 그라데이션이 됩니다 — 경계선이 뚜렷하게 그어지지 않고, 지평선 시야 제한 덕분에 "어느 순간 분위기가 달라졌다"는 식으로만 체감됩니다.

### 4-3. 오브젝트 스캐터 — 지역별 밀도·비율

기존 `scatterObstacles(minR, maxR, count)`는 반경 구간만 알고 방위는 모릅니다. 여기에 `regionAt(p.x, p.y)`로 소속 지역을 판정해서, 나무/바위 비율(`treeRatio`)과 밀도 배수(`densityMul`)를 지역 값으로 덮어씁니다. 전체 오브젝트 개수(현재 240개)의 총합은 유지하되, 지역별로 재분배하는 방식이라 로드맵 1에서 확정한 전체 밀도감은 크게 변하지 않습니다.

### 4-4. 구역 진입 알림 — 가벼운 토스트

에버그린처럼 "지금 어느 지역인지" 알려주기 위해, 처음 그 지역에 들어설 때 기존 `showToast()`를 재사용해 지역 이름을 한 번 띄웁니다 (예: `오래된 숲에 들어섰습니다`). 랜드마크 발견 토스트와 마찬가지로 지역당 1회만 표시하고, 방문 여부는 탐험 격자와 별개로 5개 지역에 대한 작은 불리언 배열 하나만 추가하면 됩니다.

### 4-5. 손대지 않는 것

- 기존 5개 랜드마크의 좌표·이름·발견 로직은 그대로 둡니다.
- 포탈 좌표(650, 1126)·전환 로직도 그대로 둡니다. 폐허 관문 구역 안에 자연스럽게 포함될 뿐입니다.
- 미니맵/전체 지도는 이번엔 지역 이름을 표시하지 않습니다(지도 UI가 복잡해지는 걸 피하려고 필드에서의 토스트로만 알림). 지도에 지역 라벨을 넣을지는 다음 로드맵에서 재검토합니다.

## 5. 작업 순서

1. `bearingOf()` / `regionAt()` 헬퍼 추가, `REGIONS` 정의
2. `scatterObstacles`에 지역별 `treeRatio`·`densityMul` 반영 — 리팩터링 후 **총 오브젝트 개수와 랜드마크 근접 제외 로직은 그대로 유지되는지** 확인
3. `terrainPatches` 생성·렌더링에 `groundTint` 반영
4. 지역 방문 여부 배열 + 진입 시 토스트 1회 표시
5. Playwright로 5개 구역을 순서대로 가로질러 걸어보면서 스크린샷 확보 — 구역마다 톤이 실제로 다르게 보이는지, 경계에서 부자연스러운 끊김이 없는지 확인
6. 데스크톱/모바일 60fps 유지, 콘솔 에러 없음 확인 후 배포
