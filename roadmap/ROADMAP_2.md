# 로드맵 2 — 미니맵 · 전체 맵(M) · 랜드마크

**상태: 확정 · 구현 완료**
로드맵 1이 남긴 과제 — "걸어도 아무것도 남지 않는다", "어디로 갈 이유가 없다" — 를 푸는 단계입니다.

이번에 만드는 것은 두 가지입니다.

1. **탐험 기록 + 미니맵(상시) + 전체 맵(M키)** → 걸은 것이 남는다
2. **랜드마크 + 발견 시스템** → 걸어갈 이유가 생긴다

이 둘이 합쳐지면 **"걷는다 → 새 지역이 드러난다 → 지도에 남는다 → 멀리 보이는 목표로 다시 걷는다"**는 순환이 처음으로 완성됩니다.

---

# A. 탐험 기록과 지도

## A-1. 핵심 설계 원칙

**지도는 절대 전체를 미리 보여주지 않습니다.**
처음부터 행성 전체가 보이면 힘들게 만든 지평선 제한이 통째로 무의미해집니다. 미공개 지역은 흐리게가 아니라 **완전히 가립니다.** 발견의 쾌감은 "안 보이던 게 보이는 것"에서 나옵니다.

**칠하는 기준은 "밟은 자리"가 아니라 "본 자리"입니다.**
지나간 좌표만 칠하면 지도에 실 같은 선만 남아 성취감이 없습니다. 플레이어 주변을 원으로 칠해야 실제 경험과 지도가 일치합니다.

## A-2. 탐험 판정 반경 — 804가 아니라 **500**

여기가 이번 작업에서 가장 중요한 수치 결정입니다.

시야 반경은 804지만, **탐험으로 인정하는 반경은 500**으로 잡습니다. 이유가 두 가지입니다.

**첫째, 804는 사실 "본 것"이 아닙니다.** 투영 수식상 거리에 따른 축소율은 이렇습니다.

| 거리 | 축소율 | 체감 |
| --- | --- | --- |
| 500 | 57% | 형태를 확실히 알아봄 |
| 545 | 50% | 알아볼 수 있음 |
| 658 | 30% | 뭔가 있다는 정도 |
| 804 | 2.4% | 사실상 점, 안 보이는 것과 같음 |

지평선 근처는 극단적으로 압축돼서 실제로는 알아볼 수 없습니다. 500까지만 인정하는 게 오히려 정직한 처리입니다.

**둘째, 804로 잡으면 게임이 시작하자마자 끝납니다.** 스폰 지점에 가만히 서 있기만 해도 행성 전체의 **28.7%**가 즉시 공개됩니다. 500이면 **11.1%**로 시작합니다.

### 짚고 넘어갈 문제: 행성이 좀 작습니다

정직하게 적어두면, 이동 속도가 200/초이므로 반경 500 기준 **이론상 최단 40초 정도면 행성 전체를 다 볼 수 있습니다.** (중심에서 반경 1000 지점으로 나가 한 바퀴 돌면 끝) 실제로는 장애물과 비효율적인 경로 때문에 1~2분 정도 걸립니다.

프로토타입 단계에서는 이대로 진행해도 괜찮지만, **구역·몬스터가 들어오는 시점(로드맵 3 이후)에 `WORLD_RADIUS`를 2500~3000으로 키우는 것을 전제로 둡니다.** 지금 미리 키우면 240개 오브젝트가 흩어져서 오히려 휑해집니다.

## A-3. 데이터 구조

- 행성 전체를 **50단위 격자**로 분할 → 원 안에 약 2,827셀
- 방문 여부를 불리언 배열로 보관
- 매 프레임 전체를 순회하지 않고 **플레이어 주변 바운딩 박스(약 21×21 = 441셀)만 검사**
- 갱신 주기는 매 프레임이 아니라 **이동 거리 25단위마다** 한 번이면 충분
- 탐험도 % = 켜진 셀 ÷ 원 안 전체 셀

이 배열이 나중에 저장 기능(로드맵 3 이후)의 첫 번째 저장 대상이 됩니다.

## A-4. 렌더링 방식

매 프레임 2,827셀을 다시 그리면 낭비이므로, **오프스크린 캔버스에 탐험 영역을 누적**해 두고 미니맵·전체 맵은 그것을 복사해서 씁니다. 새로 열린 셀이 있을 때만 오프스크린에 추가로 칠합니다.

## A-5. 상시 미니맵 (우측 상단)

| 항목 | 사양 |
| --- | --- |
| 위치 | 캔버스 우측 상단, 여백 16px |
| 모양·크기 | 원형. 데스크톱 지름 140px, 모바일 100px |
| 배경 | 반투명 어두운 색 (미공개 지역) |
| 표시 내용 | 탐험 영역, 플레이어 위치·바라보는 방향, 발견한 랜드마크 아이콘, 행성 경계선 |
| 방향 | **북쪽 고정** (카메라가 회전하지 않으므로 미니맵도 회전 불필요) |
| 힌트 | 미니맵 아래 `M` 표시 — 전체 맵을 열 수 있다는 안내 |

## A-6. 전체 맵 (M키)

| 항목 | 사양 |
| --- | --- |
| 열기 | 키보드 `M` / 모바일은 **미니맵을 탭** |
| 닫기 | `M` 한 번 더, 또는 `ESC` / 모바일은 맵 바깥 탭 |
| 크기 | 화면 중앙, 지름 = 화면 짧은 변의 약 70% |
| 게임 진행 | **일시정지.** 지금은 전투가 없으므로 정지가 자연스럽고 안전합니다. 전투가 들어오는 시점에 "맵 보는 동안 무방비" 방식으로 바꿀지 재검토합니다. |
| 추가 표시 | 탐험도 %, 발견한 랜드마크 이름 라벨, 발견 개수(예: `발견 2/5`) |

# B. 랜드마크와 목표

## B-1. 배치

기존 샘물을 포함해 **5개**를 배치합니다. 멀리서 윤곽만 봐도 구분되도록 실루엣을 확실히 다르게 만듭니다.

| 이름 | 위치 (x, y) | 중심 거리 | 실루엣 |
| --- | --- | --- | --- |
| 샘물 지대 | (230, -110) | 254 | 기존 자산. 시작 지점 근처의 첫 발견 |
| 거대 고목 | (100, -1150) | 1154 | 아주 높고 넓게 퍼진 수관 |
| 바위산 | (1180, -200) | 1197 | 뾰족하게 솟은 층진 바위 |
| 석조 유적 | (-950, 780) | 1229 | 무너진 기둥 여러 개 |
| 빛나는 결정 | (-1250, -350) | 1298 | 가늘고 길게 솟은 발광체 |

중심에서 1150~1300 구간에 방향을 흩어 배치했습니다. 스폰 지점(0,0)에서는 대부분 보이지 않고, 걸어 나가야 하나씩 드러납니다.

## B-2. 원거리 가시성 — 높은 것은 지평선 너머에서도 보인다

현재 `project()`는 거리가 `HORIZON_D`를 넘으면 무조건 그리지 않습니다. 랜드마크에는 **높이(height) 속성**을 주고 가시 거리를 늘립니다.

```
가시 거리 = HORIZON_D + height × 4        // height 50~120 → +200~480
```

가장 높은 랜드마크는 약 1,285까지 보이므로, 스폰 지점에서도 거대 고목의 꼭대기 정도는 아슬아슬하게 시야에 걸립니다. **"저 멀리 뭔가 보인다 → 저기로 가보자"**가 게임 시작 직후부터 작동합니다.

**이건 눈속임이 아니라 실제 구체 기하학과 맞는 처리입니다.** 지구에서도 수평선 너머의 배는 돛대부터 보입니다. 구체 투영을 수식으로 구현해 둔 덕분에, 물리적으로 올바른 동시에 게임적으로도 유용한 드문 경우입니다.

지평선 너머에 있을 때는 **아래쪽이 잘린 실루엣**으로 그려서, 가까이 갈수록 전체가 솟아오르는 느낌을 냅니다.

## B-3. 발견 시스템 = 이번 단계의 "간단한 목표"

- 랜드마크 **120 이내로 접근하면 발견 처리**
- 발견 시:
  - 화면에 토스트 알림 — `샘물 지대를 발견했습니다`
  - 미니맵·전체 맵에 아이콘 **영구 표시** (다시 찾아갈 수 있게)
  - HUD 카운터 증가 — `발견 2/5`
- 5개 전부 발견하면 축하 메시지

`발견 n/5`가 이 게임 최초의 목표 지표입니다. 전투나 레벨보다 먼저 플레이어에게 "나아가고 있다"는 감각을 줍니다.

## B-4. 함께 정리할 것

HUD의 `좌표 X 0000 / Y -0060`은 개발용 정보입니다. 플레이어에게는 **스폰 지점 기준 방향과 거리**(예: `출발점에서 남동쪽 420m`)가 훨씬 쓸모 있으므로 이번에 같이 교체합니다.

# C. 작업 순서

1. 탐험 격자 + 오프스크린 누적 렌더링
2. 상시 미니맵 (우측 상단)
3. `M` 키 전체 맵 + 일시정지 + 모바일 탭 대응
4. 랜드마크 5종 배치 및 그리기
5. 높이 기반 원거리 가시성 + 지평선 실루엣
6. 발견 판정 + 토스트 + `발견 n/5` 카운터
7. HUD 좌표 → 방향·거리 표시로 교체
8. Playwright 검증 후 배포

# D. 완료 기준 (검증 완료)

Playwright 자동 테스트로 데스크톱(1100×850)·모바일(390×780, 터치) 양쪽에서 확인했습니다.

- [x] 시작 시 탐험도 **정확히 11%**, 미공개 지역은 완전히 가려짐
- [x] 걸으면 미니맵이 실선이 아니라 면으로 채워짐 (11% → 18% → 27% 증가 확인)
- [x] `M`으로 전체 맵이 열리고 게임이 멈춤, `M`/`ESC`로 닫힘 (정지·재개 모두 확인)
- [x] 모바일에서 미니맵 탭으로 전체 맵이 열리고, 지도 밖 탭으로 닫힘
- [x] 랜드마크가 지평선 너머에서 꼭대기만 보이고, 다가가면 전체가 솟아오름
- [x] 접근 시 토스트 + 미니맵 아이콘 영구 표시 + 카운터 증가
- [x] HUD가 방향·거리로 바뀜 (`출발점` → `북 443m`)
- [x] 데스크톱 60fps · 모바일 61fps, 콘솔/페이지 에러 없음

# D-2. 구현하면서 바뀐 것

계획대로만 가지 않은 부분이 두 가지 있어서 기록해 둡니다.

**1. 먼 랜드마크의 최소 배율을 0.16 → 0.32로 올렸습니다.**
처음 계산대로 만들었더니 스폰 지점에서 거대 고목이 화면상 약 4px로 찍혀서, 이론상으로는 "보이는" 게 맞지만 실제로는 아무것도 안 보였습니다. 최소 배율을 0.32로 올리고 가라앉는 정도(sink)도 0.65에서 멈추도록 해서, 가장 먼 거리에서도 지평선 위로 형태가 인식되는 크기(약 19px)가 나오게 했습니다. 멀수록 옅어지는 처리도 함께 넣었습니다.

**2. 충돌 처리에 "미끄러짐"을 추가했습니다 (계획에 없던 작업).**
테스트 중에 나무를 정면으로 들이받으면 플레이어가 완전히 멈춰서, 좌우로 흔들어야만 빠져나올 수 있다는 걸 발견했습니다. 기존에도 있던 문제였지만 이번 단계의 핵심이 **"멀리 보이는 랜드마크를 향해 걸어간다"**인 만큼 그대로 두면 기능 자체가 성립하지 않아서, 막혔을 때 진행 방향을 조금씩 틀어 장애물을 타고 미끄러지도록 고쳤습니다. 북쪽으로 걸었을 때 777m에서 멈추던 것이 이제 경계(1473m)까지 막힘 없이 이어집니다.

이 밖에 모바일에서 화면이 축소돼 보이던 문제(viewport 메타 태그 누락)도 함께 고쳤습니다. 아티팩트로 띄울 때는 감싸는 틀이 넣어줬지만, 깃허브 페이지로 직접 서비스하면서 드러난 문제입니다.
